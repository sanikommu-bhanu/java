Stage 2 design: ExecutorService + Callable<Double> + Future; ConcurrentHashMap for shared results (no global lock); future.get() throws ExecutionException whose cause classifies the failure, so one bad file never stops the run.

Stage 4: recommended pool size = as many threads as the waiting/IO allows up to a point; beyond the number of cores, CPU-bound work gains nothing and adds scheduling cost. Limitation: results are only in memory.
ALTERNATIVES: parallelStream uses the common pool (1 worker here) and offers less control over failures/pool size; one thread per file = 10,000 stacks (~10 GB address space).
