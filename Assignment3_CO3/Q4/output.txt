---- NOTES / ANSWERS ----
STUDENT A: extending Thread is simple but uses up the single inheritance slot; Runnable separates the task from the thread and works with executors (preferred). run() called directly executes on the main thread (shown: 'main'), start() creates a new thread (shown: 'station-probe'). Life cycle: NEW -> RUNNABLE -> TIMED_WAITING (sleep) -> TERMINATED; join() makes main wait until every station is TERMINATED, so the total is printed after all finish.
STUDENT B: 10 runs gave different finish orders; priorities did not impose an order (they are only hints to the scheduler); a daemon thread is killed when main ends (the 'DAEMON FINISHED' line never appears).
JOINT: the scheduler decides interleaving, so a correct program must not rely on order (use join/locks).
ALTERNATIVE (fixed pool of p threads): n tasks finish in about n/p rounds; memory = p thread stacks instead of one thread per station.
