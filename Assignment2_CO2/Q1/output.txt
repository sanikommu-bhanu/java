---- NOTES / ANSWERS ----
PREDICTION: '+' in a loop creates a new String each time and copies all earlier characters -> O(n^2); StringBuilder O(n); StringBuffer O(n) but synchronized (slightly slower).
OBSERVED: for short tickets all three are close (noise/JIT dominates); for the 2,000-field ticket '+' is ~100-200x slower. Prediction supported; the 'negligible' view is only true for tiny tickets.
String.join/StringJoiner behave like a builder (O(n)); String.format per field is much slower.
DESIGN DECISION: per-ticket text is owned by one thread -> StringBuilder. Shared booking log appended by several threads -> StringBuffer (or a synchronized/concurrent logger). NOTE: this sandbox has ONE CPU core, so the StringBuilder race did not show here; on a multi-core machine StringBuilder usually loses characters or throws ArrayIndexOutOfBoundsException.
Complexity: + : O(n^2) characters copied, ~n temporary Strings; StringBuilder O(n) with amortised doubling, 1 buffer.
