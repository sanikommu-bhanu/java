---- NOTES / ANSWERS ----
Design: separate Comparator objects (Team has several valid orders; Comparable allows only one 'natural' order) built with comparingInt(...).reversed().thenComparing(...). Leaderboard<T> takes any Comparator<? super T>, so the same class ranks players, colleges, quiz teams; a bounded method <T extends Comparable<? super T>> and List<? extends T> show bounded types and wildcards.
Why Bisons is above Panthers: equal points (9) and goal difference (4), so the final tie-breaker (name A-Z) decides.
Correctness argument: each key comparison is a total order; thenComparing applies the next key only when the previous is 0, so the result is antisymmetric, transitive and consistent for equal items. The subtraction comparator (b.points - a.points) overflows for extreme values (shown: returns a wrong sign) and breaks transitivity.
ALTERNATIVES: Comparable = 1 sort, but one fixed order; three stable sorts = 3 x O(n log n) (same result, shown above) and more work/space; the Comparator chain is the most reusable.
