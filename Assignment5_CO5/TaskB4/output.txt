---- NOTES / ANSWERS ----
Migration.java reads the old file, validates every line, reports failed records with line numbers, loads the valid rows with PassLoader.loadAll in one transaction and prints DatabaseMetaData (product, driver, tables). Above: real dry run (no database here) with the failure report; below: SAMPLE output of the database part.
Production decision for 12 campuses, 100x data, concurrent counters: a database (MySQL). Text files: O(n) search, no concurrent-write safety; serialization: whole-object load, version fragility, no concurrency control; the database gives indexes (O(log n) search), transactions, constraints (UNIQUE pass_id) and concurrent access.
ALTERNATIVE (one serialized file per campus): searching all passes = 12 separate loads (O(total)), data duplicated per campus and concurrent counters need file locking, so two counters can overwrite each other.
